The design: on the Profiles list, once the knob has rested MENU_PREVIEW_MS (600 ms; menu_tick()'s idle_ms is the time since the last knob input), the saved profile under the cursor shows: its lighting (on/off, effect, HSV, speed) and the LCD's level, set unsaved. It runs as a new edit field, ME_PROFILE, of P1b's edit transaction (menu_edit.c): me_open() snapshots the RGB config and the LCD level in the edit's existing 9 B; restore() puts both back; the RGB flush stays held while it's open (menu_edit_rgb_open()); an RGB or an LCD external writer rolls it back (in_domain()). prof_preview() sets only the fields that differ (a mode set restarts its animation). menu.c's pv (1 B) says what shows: a slot, PV_LIVE, or PV_HELD (an external write rolled it back: the live settings until the next knob input). A click on a slot previews at once and its page keeps it; Load (prof_load(), the saving setters) then me_keep() closes the edit without the snapshot back; Save current here's confirm shows the live settings and the return to the page shows the profile again; Save new, the rows Back and Save new, leaving Profiles, a delete, the menu's close (panel_owner's rollback) and a host restore's pop show the live settings. The dev hook 0x40 now cancels previews before it captures. The heap gap is 136 B; host tests pass.
