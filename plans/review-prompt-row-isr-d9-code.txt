What it does: the committed frame led_state[] (bytes) becomes led_w[81][3], the pulse widths in ticks in the pins' order R, B, G; the handler's step 4 (rowisr_hot) loads the width from it instead of width_lut[], and a value above ROWISR_TERMINAL is a dithered tick (DITHER_HALF 0x8000: one tick every second field, DITHER_QUARTER 0xC000: every fourth) resolved against field_phase, advanced when cur_row wraps. The flush (sn32f2xx_flush) converts the 8-bit render buffer into led_w[] unmasked: on the wide path (an effect whose value is uniform across the frame told the driver the value through sn32f2xx_wide_frame(v), from the board's rgb_matrix_hsv_to_rgb() wrap in power.c, which then converts the colour at full value so the bytes hold the chroma), width = chroma x curve_q6[v] x ROWISR_K_Q6 with a per-frame reciprocal at Q8 (wide_width), under a tick a dithered tick or dark; on the byte path (any other frame, and a frame the dev pattern overwrote: rowisr_diag.c calls sn32f2xx_wide_cancel()), width_lut[byte] as before. A value change alone (the chroma bytes unchanged, so set_color's change check sets nothing) forces the flush through wide_v's comparison. The whitelist in power.c: Solid, Alphas/Mods, the three Cycles, Jellybean; Typing Heatmap, RAINFALL and DRIFT keep the byte path. The RX tap (bluetooth/ch582f_ajazz.c, ops 15-16 in hid_protocol.c) is opt-in under CH582_RXTAP for the RAM (the dev gap 368 -> 344 B with the wide frame).
