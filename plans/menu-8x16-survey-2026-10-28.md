# The 8x16 menu: what the firmware assumes about 6x14 (survey, 2026-10-28)

A read-only survey of the menu firmware at `3b6e43ef73` (the board's
`font-test`, which is `ecb10f0e9b` plus the dev Font test page), made for
[MENU-8X16-PLAN.md](MENU-8X16-PLAN.md). It lists every place that encodes the
Cozette 6x14 cell, the 20 x 8 grid or a position derived from them, with its
value at 8x16. The 8x16 values come from the mock-up's `geometry()` (core.js),
which lays out every page at 8x16. Line numbers are as of that commit.

The mock-up's files (`core.js`, `icons16.js`, `mkfont8.js`, `f-termb.hex`)
were in a session scratchpad under `/private/tmp` when this was written; the
plan moves them into the repo.

## 1. Constants and expressions encoding the geometry

**Cell and grid**
- `menu_text.h:13-14`: `MT_CELL_W 6`, `MT_CELL_H 14` → 8, 16 (CW, CH). Asserted equal to the face at `menu_text.c:9`.
- `menu.h:63`: `MENU_ROWS 8` → 7 (ROWS).
- There is no column constant. The literal `20` appears in `menu.c` at:
  - 1053, 1056 (`20u - 2u - vn - 1u`), 1064 (`n <= 18u ? 2u : 20u - n`)
  - 1078-1079, 1084, 1090, 1096, 1114, 1116, 1159, 1161
  - 1370 (`20u`), 1427 (`mt_line_t {cells, 20, …}`)
  - 1473-1474, 1486, 1605-1606, 1614, 1782-1783
  - All become 15 (COLS). A `MENU_COLS` define would cover them all.
- `menu_backend.h:16-17`: `MB_GLYPH_W 6` / `MB_GLYPH_H 14` are FONT_SMALL's cell (the flash atlas). They are not the menu face; keep them (see §7).

**Title and separator**
- `menu.c:1487`: `text_piece(cells, 0, …)` draws the title at y 0 with all 14 glyph rows. The target is TITLE_Y −1 (`core.js:141, 731`): glyph rows 1-15 at y 0-14.
  - `y` is `uint16_t` everywhere, so −1 can't be passed. `text_piece` needs a first-glyph-row offset for the title.
  - Pieces stay 4 (15 rows at 4 a piece).
- `menu.c:1460`: `mb_fill(4, 14, 123, 14, …)` → y 15 (SEP_Y).

**List geometry** (`menu.c:856-869`)
- `S_TITLE 0`, `S_SEP 1`, `S_BAR 2`, `S_ROW0 3`: unchanged.
- `ROW_Y0 15` → 16 (ROW0).
- `ROW_H 14` → 16 (ROW_H).
- `TEXT_X 4` → 4.
- `ROW_LEAD 4` → 4. core.js uses lead 4 for a row and 1 for a title or page line (`core.js:710`).
- `HALF_W (10u * MT_CELL_W)` is 60 today. **As written it becomes 80, which is wrong.** core.js has no counterpart (it draws per pixel).
  - Keep the pixel split at 60: `MENU_COLS*MT_CELL_W/2` = 60 for both faces.
- `CHUNK_MAX (HALF_W + 1u)`: 61 with HALF_W 60 (81 as written).
- `BAR_X 125` → 125.
- `BAR_Y0 15` → 16.
- `BAR_H (MENU_ROWS * ROW_H)`: 112 → 7×16 = 112, the same value.
- `BITS_MAX 64` (`menu.c:869`): see §2.
- `L_LIST {11, …}` (`menu.c:1526`): the hard-coded 11 must become 10 (3 + MENU_ROWS).

**Row contents**
- Battery note (`menu.c:952-954`): `r >= 5u && r <= 7u` and `x.line = r - 5u` → rows 4-6, `r - 4` (NOTE_ROW0 4, `core.js:347`).
- Profile summary (`menu.c:101-102`): `PSUM_ROW0 5u`, `PSUM_LINES 3u` → 5, 2 (`core.js:144, 348`).
- Summary rule (`menu.c:1499-1500`): y = ROW_Y0+5·ROW_H, 85 → 96, x 4-123 (`core.js:749`). Terminus Bold inks row 0 only for '`', so the rule row stays clear.

**Bulb**
- `BULB_X 111` (`menu.c:1369`) → 111.
- `BULB_CHUNK_W (TEXT_X + 20u * MT_CELL_W + 1u - BULB_X)` (`menu.c:1370`): 14 today. As written at 8 px it becomes 54; with 15 columns it is 14.
- Vertical offset: `bulb_row` (`menu.c:1387-1389`) passes art row = slot row, and the bulb height is ROW_H (`menu.c:1493`). Target BULB_DY 1 (`core.js:144, 727`): pass `(uint8_t)(row - 1)`. `power_bulb_row` already returns the background for y ≥ BULB_H (`power_bulb.c:75-79`).
- `BULB_W 13`, `BULB_H 14` (`power_bulb.h:14-15`): unchanged.

**Chunks and pieces** (no counterpart in core.js for any of these)
- `RULE_CHUNK 3u` (`menu.c:1358`) is a chunk index; it stays 3.
- `SPLIT_W (HALF_W - 2u * MT_CELL_W)` (`menu.c:1396`): 48 → 44.
- `text_piece` icon chunk width `2u * MT_CELL_W` (`menu.c:1441`): 12 → 16.
- `rows = MT_CELL_H` (`menu.c:1449`): 14 → 16.
- Window comments at 1433-1444: [0,61), [61,122), [4,64), [64,125), [16,64), [64,111). With HALF_W 60 they become the same pixel windows, except split [20,64) and icon [4,20).

**Confirm pages**

- `info_y` (`menu.c:1550`): {22,36,50,86} → {24,40,56,96} (INFO_Y).

## 2. Static asserts and cell-sized buffers at 8x16

These assume COLS 15 and HALF_W kept at 60.

**Asserts that fail or sit at a limit**

| Location | Check | Result at 8x16 |
|---|---|---|
| `menu.c:103` | `sizeof pslot_rows(5) <= PSUM_ROW0(5) && PSUM_ROW0 + PSUM_LINES <= MENU_ROWS` | **Fails** with PSUM_LINES 3 (8 ≤ 7). With 2: 7 ≤ 7, **at the limit**. |
| `menu.c:311` | `1 + CLOCK_ROWS <= MENU_ROWS` | 7 ≤ 7, **at the limit** (the Clock page fills the screen exactly). |
| `menu.c:1371` | `BULB_CHUNK_W == BULB_W + 1u` | Holds (14 = 14) only once the `20u` is fixed; 54 as written. |
| `menu.c:1371` | `BULB_H == ROW_H` | **Fails** (14 vs 16). Replace with `BULB_DY + BULB_H <= ROW_H` (1+14 = 15 ≤ 16). |
| `menu.c:1418` | Icon chunk `2·MT_CELL_W·MT_CELL_H·2 <= MB_PASS_BYTES` | 2·8·16·2 = **512 = MB_PASS_BYTES, exactly at the limit**. Bits: ⌈16/8⌉·16 = 32 ≤ 64. |
| `menu_fixture.c:143` | `TEXT_W == ROW_X1 - ROW_X0 + 1`, where `TEXT_W = 1 + 20*MT_CELL_W + 1` (line 140) | **Fails**: 162 ≠ 122. `menu_fixture.c` is in every firmware build (`rules.mk:62`), so the firmware won't compile. With 15 cells it is 122 and holds. |

**Asserts that still hold**
- `menu.c:312`: `sizeof pg == sizeof(env_about_t)` (12 B), unchanged.
- `menu.c:1372`: 14·16·2 = 448 ≤ 512.
- `menu.c:1413` (half piece): 512/122 = 4 ≥ 1; 4·⌈61/8⌉ = 32 ≤ 64.
  - With HALF_W left at 80 it would also pass (3·11 = 33), even though that geometry runs off the panel. The assert gives no protection there.
- `menu.c:1415` (split): 512/88 = 5 ≤ 16; 5·⌈44/8⌉ = 30 ≤ 64.
- `menu.c:1417` (lead): 4·16·2 = 128 ≤ 512; 4 ≤ 8; 16 ≤ 64.
- `menu.c:1789-1791`: 22 slots ≤ 24; hue band 8·21·2 = 336; range band 16·10·2 = 320 (both bands keep their heights).
- `menu.c:1810-1811`: the Font test's; they go with it.
- `menu_text.c:9-10`: hold once the generated header is 8/16 with 44 extras.
- `menu_fixture.c:82`: 276 ≤ 512.
- `menu_fixture.c:160-163`:
  - With TEXT_W 162: 512/324 = 1; 4·8 = 32; 1·21 = 21.
  - With TEXT_W 122: 2; 32; 2·16 = 32.

**Buffers and piece counts**

| Item | 6x14 now | 8x16 |
|---|---|---|
| `rows_per_piece()` (`menu.c:1391`), 512/(CHUNK_MAX·2) | 4 | 4 |
| `rows_per_split()` (`menu.c:1397`), 512/(SPLIT_W·2) | 5 | 5 |
| `l_pieces` (`menu.c:1411`), half: ⌈CH/4⌉ | 4 (4,4,4,2) | 4 (4,4,4,4) |
| `l_pieces`, split: ⌈CH/5⌉ | 3 | **4** (5,5,5,1) |
| Unsplit row | 1+4+4 = 9 | 9 |
| Split row (icon) | 9 | **10** |
| Split row + bulb | 10 | 11 |
| Ruled summary row | 10 | 10 |

- To get 3 split pieces back, SPLIT_W must be ≤ 42 (6 rows·84 = 504).
  - Option: left half 58 px and right half 62+1 = 63 px. That gives CHUNK_MAX 63 (still 4 rows a piece) and split rows of 9 pieces.
  - It needs asymmetric halves, because `text_piece` uses `HALF_W + 1` for the right half (`menu.c:1435, 1444`). The Clock's x 64 boundary would move to 62.
- Cell-aligned splits are worse:
  - 8 cells (64 px): a 65 px half → 3 rows a piece → 6 pieces a half.
  - 10 cells: x 84–164, off the panel.
- `bits[BITS_MAX]` (`menu.c:1451`, stack): the most used at 8x16 is 32 B (lead 16, icon 32, half 32, split 30, bulb row's right chunk 4·6 = 24). 64 is enough.
- `menu_fixture.c:191` `bits[64]`: F3 at 15 cells uses 32 (half) or 32 (full).
- `cells[21]` at `menu.c:1459` (l_paint), 1603 (c_paint), 1780 (e_paint): can shrink to [16] (stack). Only safe if every `20` literal changes in the same patch.
  - `row_text` writes `out[20]` (`menu.c:1079`); `prof_summary` writes up to `out+19` (1053).
  - `cells[VAL_CELLS+1]` (1775) is unaffected.
- Host test buffers: `bb[14*17]` (`test:924`) → 16·17; `b[2*16]` (`test:984`) is enough.

## 4. Behaviour core.js's wide mode has that menu.c lacks

- **A 7-row page.**
  - All of §1's paging follows MENU_ROWS.
  - Page counts at 7 rows:
    - Top level: 14 = 7+7.
    - Effect: 10 = 7+3.
    - Profiles: up to 9.
    - Lighting: exactly 7.
    - Clock: exactly 7.
  - Scrollbar (`menu.c:1464-1470`; `core.js:732-740`):
    - th = ⌊(112·7 + n/2)/n⌋.
    - Top level: th 56; page 2 thumb y 72–127 (today 63–126).
    - Shortcuts (15 lines): th 52.
    - About (8 lines): th 98, at top 1 y 30–127.
  - Topic last tops: {0,4,8,8} (today {0,0,4,5}). Paging by 7, clamped to lines−7, runs 0 → 7 → 8.
- **About scrolls** (`core.js:346, 589-592`).
  - `row_at` (`menu.c:946-950`) sets `x.line = r`. It needs `f->top + r`, and blank at ≥ 8.
  - `menu_input` (`menu.c:2403-2412`) pages only `is_topic`. Add N_ABOUT: lines 8, maxtop 1.
  - `bar_state` already counts 8 (`menu.c:1313`).
  - Optional: `menu_cursor` (`menu.c:2618-2630`) could report About's top, as it does for topics.
  - No new state is needed: `frame_t.top` exists.
- **Power's top-level row as its bulb** (`core.js:408, 747`).
  - Lands in `row_text` (`menu.c:1130`: no value).
  - `row_bulb` (`menu.c:1373`): also `N_POWER` on the top level, mode from `x->val`.
  - `l_paint`'s bulb mode (`menu.c:1492`: `x.node - N_POW0`).
  - `l_first` (`menu.c:1517-1521`) compares bits 8-15 only. **For N_POWER it must compare val (bits 4-7) too, or a Fn+B mode change keeps the old bulb.**
  - That row then has lead + icon + split + right + bulb = 11 pieces.
- **Profiles' top-level row shows the active profile's name** (variant "iv", the default; `core.js:179, 409-413`).
  - Label = the name cut to 11 (10 + "*"), or "Profiles"; value ▶.
  - Lands in `row_text` (`menu.c:1137`) and `prof_value` (`menu.c:1013-1026`, room 9/8).
  - The signature (val = slot, line = star) already exists. Names repaint by invalidation as today.
- **Clock rows show the live example as the label** (`core.js:404`).
  - Check box + "13:45:01", "Off" for row 6, no value.
  - Lands in `row_text` (`menu.c:1132`).
  - **`l_first`'s right-half-only repaint (`menu.c:1513-1525`) and `clock_sig`'s 'wide' bit (`menu.c:1248-1265`) must be redone.** The left-aligned text breaks the assumptions:
    - 24h and 12h minute digits are at x 44-59, in the left half.
    - 12h:ss seconds at 1-9 o'clock span x 60-75, across x 64.
    - 24h:ss and 2-digit-hour 12h:ss seconds are at x 68-83, right half only.
  - A right-half-only repaint would leave stale digits.
- **Help in 15 columns** and the reworded confirms, About and battery note: §3.
  - Help comes from `gen_menu_text.py` (`COLS = 20` at line 28; `TOPICS` at line 27 needs "Menu basics"). Its source is `MENU-TEXT.md`'s fenced blocks (limits at lines 17-33 say 20 columns and 8 rows).
  - The `FACTS` regexes (`gen_menu_text.py:70-77`) still match the wide text: "60 seconds idle", "Balanced sleeps after 20 min".
- **Profile summary in 2 lines**, from cell 0, in the new format: `prof_summary` (`menu.c:1034-1074`) plus the PSUM constants.
- **Battery notes on rows 4-6**: `menu.c:952-954`.
- **Profiles list names cut to 11** (`core.js:405`): `menu.c:1124`.
- **Title shortening, and dropping an icon's space when needed** (`core.js:471-476`): `l_paint`'s title composition (`menu.c:1472-1487`, truncation at 1486).
- **Not modelled in core.js** (decisions for the plan):
  - The half split and piece counts.
  - Pairing's DONE, FAILED and UNSURE phases.
  - About's flavour line and "Left -".
  - The Write test rows.

## Riskiest items

1. **`mt_bits`'s 0xFC mask** (`menu_text.c:65`) drops glyph columns 6-7 without any failure. The host reference test uses the same 6 / 0xFC assumptions (`test:948-972, 997-998`), so updating only one side lets it pass wrong.
2. **Geometry left at 20 columns, 8 rows or 10 cells:**
   - `HALF_W` would put the right half at x 84–164.
   - `BULB_CHUNK_W` would be 54.
   - `L_LIST`'s 11 would draw a row at y 128.
   - The panel refuses these without a loss (`lcd_bus.c:369`), so pixels just go missing. The host fakes write out of bounds instead of failing.
   - `menu_fixture.c:143` breaks the firmware build (`rules.mk:62`).
3. **Pass budget:**
   - The icon piece is exactly 512 = `MB_PASS_BYTES`, with no margin.
   - Every icon/check row goes from 9 to 10 pieces (split pieces 3 → 4); the top-level Power row becomes 11.
   - The bulb piece grows from 392 to 448 B. It was measured at 9.7 ms; 16 rows instead of 14 suggests roughly 11 ms (an estimate, not a measurement), against the 15 ms pass mark.
4. **Stale pixels from `l_first`:**
   - The Clock's right-half rule is wrong for left-aligned examples: minutes sit in the left half, and 1-9 o'clock seconds cross x 64.
   - The bulb skip ignores val, so a top-level Power bulb would keep its old mode.
5. **Title at TITLE_Y −1:** y is unsigned, so `text_piece` needs a glyph-row offset. Passing −1 becomes 65535 and the panel refuses it.
6. **RAM (the dev build's heap gap sits exactly on its 128 B floor):**
   - The geometry needs no new static RAM if the face is swapped at compile time:
     - About's scroll uses `frame_t.top`.
     - `pg` stays 12 B (`menu.c:312`).
     - `cells[]` and `bits[]` are stack buffers.
     - Strings stay `static const` (flash).
   - Things that would add RAM:
     - Keeping both faces switchable: at least 1 B static, plus 2224 B flash.
     - Any stored composed-string buffer.
     - New per-page state outside `pg`.
   - Flash grows +278 B for the face, plus the longer Help text.
