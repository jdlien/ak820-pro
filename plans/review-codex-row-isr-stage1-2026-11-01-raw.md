# Codex review of stage 1 (the row ISR rewrite), 2026-11-01, raw

gpt-6-astra, xhigh, read-only, launched 12:05 on the worktree's stage 1 (before the hold counter fix of 12:20); the prompt is below the review.

Four P1s block flashing.

1. **P1 — overlapping holds can release the row IRQ during I2C.** The saved-enable-bit API preserves the old RTC semantics only with one owner. Sequence: op 28 saves `true`; RTC starts and saves `false`; the indicator tick ends op 28 and enables the IRQ while RTC still changes port A’s MODE. RTC’s later `release(false)` does nothing. Use shared hold ownership or prevent this overlap. References: [rowisr.c:424](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/keyboards/a_jazz/ak820pro/rgb/rowisr.c:424), [rowisr_diag.c:77](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/keyboards/a_jazz/ak820pro/rgb/rowisr_diag.c:77), [rtc.c:299](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/keyboards/a_jazz/ak820pro/rtc/rtc.c:299).

2. **P1 — tick stop/deep sleep breaks the hold’s endpoint contract and can suppress waking-key samples.** `pwm_tick_stopI()` drives D15 low without releasing the hold. Light sleep eventually reaches the housekeeping backstop, but deep sleep stops both the countdown and its deadline clock. Wake restores the saved NVIC mask with the row IRQ still disabled; scanning then waits for the remaining hold duration, potentially losing the waking press. Cancel the hold atomically before stopping the tick or entering sleep. References: [indicators.c:213](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/keyboards/a_jazz/ak820pro/indicators.c:213), [sleep.c:484](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/keyboards/a_jazz/ak820pro/sleep.c:484), [sleep.c:506](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/keyboards/a_jazz/ak820pro/sleep.c:506), [rowisr_diag.c:108](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/keyboards/a_jazz/ak820pro/rgb/rowisr_diag.c:108).

3. **P1 — the advertised hold range overflows.** `hold_ticks` is `uint16_t`, but 10,000 ms requires 200,000 ticks. Requests produce:
   - 3,277 ms → 0.2 ms
   - 5,000 ms → 1,723.2 ms
   - 10,000 ms → 169.6 ms

   These finish normally and evade the backstop. Use a sufficiently wide counter. [rowisr_diag.c:69](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/keyboards/a_jazz/ak820pro/rgb/rowisr_diag.c:69), [rowisr_diag.c:90](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/keyboards/a_jazz/ak820pro/rgb/rowisr_diag.c:90).

4. **P1 — stage 1’s early-quiesce gate is unimplemented.** `bootloader_jump()` still only stops the watchdog and resets. `sn32f2xx_blank()` has no caller and does not stop notifications/the IRQ; its thread-class PWM calls also permit callback interleaving during teardown. Now Bootmagic reaches that jump with PWM already running. Implement the common, idempotent quiesce required by D7 before the reset. This is an unmet gate, not evidence that every reset necessarily leaves LEDs lit. [watchdog.c:127](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/keyboards/a_jazz/ak820pro/watchdog.c:127), [rowisr.c:529](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/keyboards/a_jazz/ak820pro/rgb/rowisr.c:529).

**P2 — RGB-disabled dev compilation is incomplete.** The scanner compiles without RGB, but the diagnostic file unconditionally includes `rgb_matrix.h` and implements RGB-dependent code under only `AK820_DEV_HOOKS`. Removing RGB’s defines/include paths reproduces a compilation failure at [rowisr_diag.c:10](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/keyboards/a_jazz/ak820pro/rgb/rowisr_diag.c:10). Guard the pattern separately so register/hold diagnostics remain available.

The remaining checks:

[rowisr.c:254](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/keyboards/a_jazz/ak820pro/rgb/rowisr.c:254).

Diagnostics additionally change dev tick execution time. Repeated custom/RGB initialization does not restart hardware or erase acquired samples; repeated QMK `matrix_init()` still clears raw/cooked matrices, so it is not fully state-preserving. [keyboard.c:459](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/quantum/keyboard.c:459), [matrix_common.c:151](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/quantum/matrix_common.c:151).

- **IRQ semantics outside overlapping holds:** Preserved: saved enable state, pending bit retained, CMSIS disable’s DSB/ISB, no ChibiOS vector helpers. A pending request becomes serviceable on release; there is no accumulated interrupt queue.

- **Op 28:** Register bases, offsets and per-timer selections match the manual and CT structures; no selected read targets an absent register. Ordinary marker start/release pairs are locked correctly, and invalidating `ind_last_out` restores Caps on the next tick. **P2:** a Caps output already high provides no rising edge at hold start; require Caps low for the claimed endpoint measurement. A second hold is rejected. The pattern runs after every completed **nonzero-effect** render, but not while RGB is disabled/suspended/NONE. [rowisr_diag.c:41](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/keyboards/a_jazz/ak820pro/rgb/rowisr_diag.c:41), [rgb_matrix.c:458](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro-rowisr/quantum/rgb_matrix/rgb_matrix.c:458).
