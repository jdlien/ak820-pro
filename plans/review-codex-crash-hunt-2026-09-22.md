I would revise B1 and C before implementation. The main risks are a fault recorder that itself locks up, and a soak that resumes after losing settings or disabling its watchdog.

Read-only review completed against the source and instrumented ELF; no HID tools were run and no files changed.

1. **High — Frame validation does not make the fault handler safe.** B1 validates the frame pointer, but calling C still uses MSP. A valid PSP frame plus corrupted/exhausted MSP can fault in the recorder’s prologue, before validation executes. Today’s handler performs no stack accesses: [vectors.S:1021](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/lib/chibios/os/common/startup/ARMCMx/compilers/GCC/vectors.S:1021). ARM documents faults inside HardFault as lockup. **Recommendation:** use a stackless recorder, or switch to a reserved, aligned emergency stack before entering C. Preserve original SP and EXC_RETURN first; use Thumb-1 register tests/branches, not Thumb-2 `IT`/immediate-`TST` examples. Add an ISR-context HardFault test; the proposed thread test exercises only PSP. [ARM fault handling](https://documentation-service.arm.com/static/5ea6ce5e9931941038def8c1#page=43).

2. **High — Restoring one key and two RGB fields cannot recover interrupted consolidation.** The soak saves only those values ([soak.py:190](/Users/jdlien/code/ak820-pro/scripts/soak.py:190)). Consolidation erases the backing store before rewriting it; a bad checksum subsequently clears the logical cache ([wear_leveling.c:303](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/quantum/wear_leveling/wear_leveling.c:303), [wear_leveling.c:234](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/quantum/wear_leveling/wear_leveling.c:234)). **Recommendation:** persist a complete pre-run backup of keymap, encoders and all lighting settings before any stress; retain that original across reconnects. Capture crash evidence before restoration, retry restoration idempotently, and stop if verification fails. Put recovery/cleanup around all failure exits; today `finally` only closes the handle ([soak.py:326](/Users/jdlien/code/ak820-pro/scripts/soak.py:326)).

3. **High — “Keep going” eventually removes automatic recovery.** The third counted WDT reset leaves the watchdog disabled ([watchdog.c:79](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/watchdog.c:79)). Successful operation never ages that count out ([watchdog_record.c:39](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/watchdog_record.c:39)); three failures hours apart suffice. The existing soak merely warns ([soak.py:186](/Users/jdlien/code/ak820-pro/scripts/soak.py:186)). **Recommendation:** refuse degraded starts and stop stressing immediately upon entering degraded mode. Archive evidence and restore settings before any deliberate reset of the guard.

4. **Medium — NMI belongs to ChibiOS, and exception zero does not mean main loop.** This port defaults to NMI-based switching, not PendSV ([chcore.h:166](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/lib/chibios/os/common/ports/ARMv6-M/chcore.h:166)); its strong NMI handler advances PSP ([chcore.c:61](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/lib/chibios/os/common/ports/ARMv6-M/chcore.c:61)). The ELF confirms `NMI_Handler=T`, while PendSV/SVC remain weak defaults. An idle thread also exists ([chinstances.c:170](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/lib/chibios/os/rt/src/chinstances.c:170)). **Recommendation:** remove “NMI included,” preserve the port handler, and render exception zero as **thread context**. Faults inside NMI can lock up without reaching HardFault; identify that coverage limit explicitly.

5. **Medium — The packed count requires an explicit migration and commit protocol.** Existing boot code treats any count above 255 as corrupt ([watchdog_record.c:39](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/watchdog_record.c:39)). Applying that unchanged to a packed ISR fault repeatedly resets accounting to one. A reset during an inadequately ordered fault write could also expose PC under ordinary-record magic. **Recommendation:** validate each magic’s count encoding separately, extract/increment only the low byte, define unreadable-frame/unknown-exception semantics, and invalidate magic before changing payload, committing fault magic last—as boot already does ([watchdog_record.c:53](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/watchdog_record.c:53)). Test interrupted writes as well as completed records.

6. **Medium — Older decoders reject the entire health sample after a fault.** Format 2 is correctly rejected ([health.rs:89](/Users/jdlien/code/ak820-pro/ak820-agent/src/health.rs:89)), but that error propagates out of `read_health`, discarding successfully read pages 1–2 ([agent.rs:465](/Users/jdlien/code/ak820-pro/ak820-agent/src/agent.rs:465)). Ordinary CLI health also automatically requests page 5 ([macos/cli.rs:134](/Users/jdlien/code/ak820-pro/ak820-agent/src/platform/macos/cli.rs:134)). Because the record is frozen, failure persists throughout that boot. **Recommendation:** require the decoder upgrade before v7, and make future unsupported crash formats preserve base telemetry with an explicit supplemental-record error.

7. **Medium — B3’s existing diagnostic reads occur after destructive recovery.** `spiSN32FlashDmaAbort()` runs at [lcd_bus.c:737](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/graphics/lcd_bus.c:737); the console reads registers afterward at line 754. Abort clears SPI flags and NVIC pending state ([hal_spi_v2_lld.c:233](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/lib/chibios-contrib/os/hal/ports/SN32/LLD/SN32F2xx/SPI/hal_spi_v2_lld.c:233)). Also, `blit_retries` counts attempts before their outcome ([lcd_bus.c:763](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/graphics/lcd_bus.c:763)). **Recommendation:** snapshot before abort, recheck completion consistently, retain an unknown/raced category, and count retry attempts and successes separately. These observations distinguish symptoms; they do not uniquely prove three root causes.

8. **Medium — The wear budget confuses logical writes with log entries.** Backing storage is 2,048 bytes, but logical EEPROM is 1,024 bytes ([wear_leveling_efl_config.h:67](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/platforms/chibios/drivers/wear_leveling/wear_leveling_efl_config.h:67)). Its 1,016-byte log holds **127 eight-byte entries**; each entry carries at most five data bytes ([wear_leveling_internal.h:111](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/quantum/wear_leveling/wear_leveling_internal.h:111)). An eight-byte RGB configuration therefore consumes two entries ([rgb_matrix_types.h:89](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/quantum/rgb_matrix/rgb_matrix_types.h:89)). **Recommendation:** budget approximately **2,880 entries and 23 erases per sector** for 960 key flips plus 960 combined RGB saves, before other writes. `flash_writes` counts unlock-hook invocations, not entries. Sonix lists **20k minimum / 100k typical** erase/program endurance: [manual, p.264](https://www.sonix.com.tw/webapi/fl219871/SN32F297_V1.8_EN.pdf#page=264).

9. **Medium — VIA RGB save is synchronous, contrary to the soak’s model.** `id_custom_save` reaches `eeconfig_force_flush_rgb_matrix()` ([via.c:737](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/quantum/via.c:737), [rgb_matrix.c:102](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/quantum/rgb_matrix/rgb_matrix.c:102)). It bypasses the deferred task’s settle gate. **Recommendation:** correct the claimed stimulus/cooldown behavior and combine brightness/effect changes before one save. Check save acknowledgments; immediate RGB readback alone checks live configuration, not persistence across reboot.

10. **Medium — Stack painting is real, but the scan is not guaranteed minimum SP.** Both specified regions are painted ([crt0_v6m.S:198](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/lib/chibios/os/common/startup/ARMCMx/compilers/GCC/crt0_v6m.S:198)). Untouched stack allocations and values equal to the paint can nevertheless overstate headroom. The separate idle working area is outside those regions and thread filling is disabled ([chsys.c:56](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/lib/chibios/os/rt/src/chsys.c:56), [chconf.h:656](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/platforms/chibios/boards/common/configs/chconf.h:656)). **Recommendation:** label results paint-based watermarks, use bounded volatile reads, add bottom canaries, and distinguish the main-thread stack from whichever stack PSP currently selects. Make the deep-call test actually touch its allocation.

Uptime, four stack values and four counters already use 20 bytes even with 16-bit counters. Answers to the five open questions:

1. **Keep 16 bytes initially.** PC plus exception is worthwhile. Define the commit/validation contract first; consider LR/SP expansion afterward. The DFU address is derived in both writer and reader ([sn32_dfu.c:26](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/platforms/chibios/bootloaders/sn32_dfu.c:26)), so enlargement is testable, not inherently unsafe.
2. **Spin while the watchdog is armed.** This preserves existing accounting. It does not promise recovery before `watchdog_start()` or in degraded mode ([ak820pro.c:101](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/ak820pro.c:101)).
3. **No absolute guarantee.** The range/alignment check bounds frame loads into SRAM; it does not validate frame contents, protect MSP, or handle failures during exception entry.
4. **Expected yes, still verify on hardware.** Sonix specifies ILRC-clocked watchdog counting and hardware reset independently of interrupt delivery; ARM says reset exits lockup. Sonix does not explicitly discuss lockup. Make the test deliberately fault *inside* HardFault, rather than relying on a C push that a safer recorder may eliminate. [Sonix WDT, p.150](https://www.sonix.com.tw/webapi/fl219871/SN32F297_V1.8_EN.pdf#page=150).
5. **Yes: interrupted consolidation, incomplete restoration and false acknowledgment.** Use the durable original backup and fail-closed recovery from findings 2/13; archive evidence first and verify persistence before resuming stress.
