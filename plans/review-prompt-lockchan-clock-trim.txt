Review firmware commit 6a212389 in qmk_firmware-ak820pro (git -C qmk_firmware-ak820pro show 6a212389; parent 9e52400e is on JD's and gremlin's boards), plus scripts/lockchan_media_test.c's new tests (uncommitted in the main repo). It adds a rate trim of the SN32 RTC divider (P_nom) from lock-LED clock frames (type 4), because off USB nothing trimmed it: the legacy PCF discipline runs hourly and host_correction_accepted() restarts its window on every accepted set, so 10-minute frames starved it. The Mac's cut test (history/lockchan-clock-mac-cut-20261021/) measured ~2.5 ms/s drift between frames, a 1.6 s sawtooth.

Design: a window opens at every accepted non-internal host set (rtc_set_time, rtc_set_time_ms's slew and step paths), recording rtc_seconds_count, clock_gen, a new ft_sleeps (bumped in rtc_account_sleepI), rtc_credit_s and P_nom. A frame's set (RTC_SETF_FRAME 0x40, passed by ch582f_ajazz.c's lcc_set unless the frame's new LOCKCHAN_CLOCK_F_STEPPED flag says the host stepped) closes it before the step/slew math if: nothing changed, ref_state != REF_SOF, slew idle, P_nom unchanged. It computes rtc_payload.h's rtc_frame_trim: interval 300-3600 s, 50 ppm floor, 1% cap, half-step unless the sign agrees with the last trim, clamp 28000-40000. Leaving SOF (rtc_ref_task) re-anchors an intact open window. Never persisted. Op 17 sub 8 gains the trims count and last period.

Check especially: the sign and units of the trim (a second is P+1 cycles; off is target minus board); ISR/main races on P_nom, reload_pending and slew state (the ISR reads P_nom in slews and restores it); whether every path that moves the board's clock or rate invalidates the window (legacy snap and trim, wake recovery, acquisition, slews, raw HID sets, PCF writes, SOF windows, the deep-sleep accounting, light sleep); the re-anchor at SOF exit; a step path that rejects after ft_close changed P_nom; whether hosts can reach RTC_SETF_FRAME; type 4 flag compatibility (an old board rejects STEPPED, a new board accepts 0 or 1); the noise behaviour against Windows' anchor spread (p10..p90 about 7..54 ms) and the test's simulation; and RAM (heap gap now 32 B, was 56). The daemon does not yet set STEPPED; say whether it should before this is flashed.
