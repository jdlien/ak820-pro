## The review, verbatim

I found discrepancies in all three texts at firmware commit `0d8da8b797`. The most consequential are the promise that every owner will see “Charge now,” the full-pack test procedure, and the claim that every review fix has a simulator case.

### Testing and upgrade claims

- **P1 — Release “Tested,” also relevant to battery.md 787–791.** “A case for each fix from three code reviews” is false. The simulator builds `battery.c` and `power.c`, calls `power_woke()` directly, paints alerts immediately, and substitutes a debug-page flag for the real menu. Removing a fix in `sleep.c` cannot fail that suite. The review explicitly records a wake fix with no simulator case. Keep **264** as the suite total and say “The simulator covers the battery and power decisions, with regression cases for fixes in those paths. The complete stage, including physical wake, menu handling and visible alert timing, still awaits an on-board test.” [run.sh:30](/Users/jdlien/code/ak820-pro/scripts/battery_sim/run.sh:30) · [ladder.c:417](/Users/jdlien/code/ak820-pro/scripts/battery_sim/ladder.c:417) · [sim.c:57](/Users/jdlien/code/ak820-pro/scripts/battery_sim/sim.c:57) · [sim.c:89](/Users/jdlien/code/ak820-pro/scripts/battery_sim/sim.c:89) · [review disposition](/Users/jdlien/code/ak820-pro/plans/review-codex-low-reserve-2026-11-23.md:16)
- **P1 — Release “Tested.”** “It starts only an hour past the lights going off” contradicts both the firmware bullet and the code. Either low-voltage trigger can cut RGB and enter the last stage in the **same check**, including after a reset on a nearly empty pack. Replace the explanation with “The keyboard used for the soak has not yet exercised the last stage.” [battery.c:1337](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/battery.c:1337) · [battery.c:1371](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/battery.c:1371)
- **P2 — Release opening, README 118–119, and release “Tested.”** “Lasts longer” reads as a verified runtime improvement. The eight-hour discharge predates the feature. Describe the change as **designed to extend the reserve**. For the soak, name the common-panel `ak820pro-via.bin` and say its health counters **recorded** no main-loop gap ≥25 ms after the ten-second startup period. The FPB file is a separate binary built on November 26. These qualifications preserve the reported measurements. [sleep policy](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/power.c:470) · [health.c:152](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/health.c:152) · [daily manifest](/Users/jdlien/code/ak820-pro/ak820pro-builds/out/via-daily-0d8da8b797-20261124-002017.json:7) · [FPB manifest](/Users/jdlien/code/ak820-pro/ak820pro-builds/out/via-fpb-0d8da8b797-20261126-204819.json:7)
- **P2 — Release “Upgrading.”** The preservation promise needs one instruction with a real consequence: **start `flash.sh` while the old firmware is running, before pressing `Fn`+`Esc`**. If the board is already in the bootloader, the script can restore an older keymap and proceed without a current profile backup. “Nothing looks different” is also too broad. For example, a board flashed while charging can show “Charge” while its percentage is unknown. Say “The default upgrade backs up and restores your current configuration. The new reserve behavior appears when the battery runs low.” [flash.sh:127](/Users/jdlien/code/ak820-pro/flash.sh:127) · [flash.sh:185](/Users/jdlien/code/ak820-pro/flash.sh:185) · [battery.c:1185](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/battery.c:1185) · [display.c:1761](/Users/jdlien/code/ak820-pro/qmk_firmware-ak820pro/keyboards/a_jazz/ak820pro/graphics/display.c:1761)
